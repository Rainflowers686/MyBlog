# Contributing

Use the environment and database setup in [README.md](README.md). Keep
configuration values in process environment variables and follow
[SECURITY.md](SECURITY.md) when reporting a sensitive issue.

## Focused changes

Describe the behavior you are changing and the steps that reproduce it.
Keep teaching/demo behavior explicitly separated from settings for real
users. Do not add a shared account password or expose a reset token in normal
account flows.

For dependency changes, preserve existing version pins unless the change
requires an upgrade. Several dependencies were missing from the original
course list, so their original versions are unknown. Record the versions
used for a successful restored environment instead of claiming the original
environment has been reproduced.

## Checks

Run `python manage.py check` after configuring a disposable local database
environment. Changes to models need reviewed migrations; changes to account
flows need tests for both permitted and rejected requests. Never run seed,
repair or migration scripts against someone else's database for validation.

`python manage.py test core` checks missing-credential rejection, the normal
password-reset boundary and the database helper's lack of import side effects.
These tests do not use a database or send mail. The existing CKEditor warning
remains a separate deployment issue.

Check the English and Chinese README links and commands together. Do not
commit `.env` files, database dumps, uploaded media, logs, virtual environments
or `__pycache__` files. Generated bytecode is rebuilt from source.

The repository has no repository-wide license. Clarify the rights to any
external code, template or asset before adding it.
